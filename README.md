# Attention Guard（Android APK）

**Attention Guard** 是一个面向校园微信群的 Android 注意力系统：它从用户当前打开的微信会话读取消息，识别通知、截止时间和行动要求，再把分散的消息合并成可追踪的事件。用户看到的是“现在需要关注什么”和“这件事后来怎么样了”，而不是又一个聊天机器人。

当前开发版本为 **1.7 / versionCode 8**。本轮加入事件列表快捷完成与可逆归档、微信内手动识别当前聊天、Jev 框架的本地意图线索和来源标记。由于当前没有 ADB，1.7 的真机回归仍待补做；已有设备证据与未覆盖项见 [真机审计](docs/device-audit-1.5.md)。

> **当前只支持微信。** 服务仅接受前台 `com.tencent.mm` 的当前可见会话；非微信适配代码已移除。
>
> **发送始终与你无关。** Attention Guard 只读消息、只生成事件，不填入输入框，不点击发送，也不触碰转账、红包或收款界面。

<p align="center"><em>Attention Guard is a non-invasive Android attention layer for campus group chats. It observes the current WeChat conversation, builds trackable events, and keeps the final decision with the user.</em></p>

## 当前产品切片

- **注意力首页**：展示待处理、关注中和已完成事件。
- **事件观测记录本**：把一条通知的发现、补充、截止时间和规则变更串成时间线，并保留原始消息依据。列表可直接打钩完成或归档；归档可恢复，不会删除依据。
- **微信内手动识别**：悬浮窗收起时也可识别当前聊天。Jev 意图线索沿用“字面依据、可能意图、下一步”框架，在本机规则判断，不调用 Jev 在线模型，也不生成或发送回复。没有可信对方正文、OCR 待核对或回溯期间不做意图推断。
- **来源标记**：事件列表和详情区分微信自动/手动识别，详情保留采集时间、会话、发送者和原始依据；旧事件显示“来源待核对”。
- **来源**：列出实际产生事件的会话，可按来源进入观测簿；设置中用会话名关键词限制采集范围，不提供虚构的群权重开关。
- **Android 权限入口**：无障碍、悬浮窗、后台运行和模型设置都从 APK 内可达。
- **采集与回溯**：从“来源”或“我的”进入；显示运行诊断、原始消息、日期范围和任务状态。普通聊天也会保存，不再依赖事件规则命中。
- **回溯归档与复核**：每屏先落盘再翻页；相邻屏重叠查重，短时服务重连可识别同一数据流的完全相同页面。记录页会显示质量回执，包括重复候选、日期未确认和分页断点。不是全库指纹去重，不确定日期与无法拼接的页面仍可能重复。P0 需要 24 小时内的已校验期限及行动/来源信号；相邻更正、过期通知、无效日期分别复核，模型不能绕过本地等级上限。
- **结构化诊断与解释**：运行状态拆成服务连接、读取质量、落盘、悬浮窗和保活通知；事件详情明确展示“为什么是这个等级”，并说明 DeepSeek 不能越过本地证据门槛。

图标与界面采用用户选择的 **Orbit Relay** 方向：石墨底、银白与青绿轨道、小面积桃色端点。页面是原生 Kotlin View + Material Components，保留短入场与完成反馈动效，并尊重系统动画设置。

## 项目目标

- **校园注意力而不是自动回复**：系统判断“这条消息值不值得占用注意力”，再把重要内容整理成事件；不替用户做发送决定。
- **采集边界**：不 hook、不改包、不读聊天数据库、不访问聊天账号接口。普通监测只读可见节点；用户确认后可用本机 OCR，主动启动回溯后可向前翻动聊天列表。
- **兼容性需按版本验证**：保留历史服务类名，增加窗口恢复、结构匹配与不可读诊断。OCR 默认关闭，须单独确认；没有可靠聊天气泡证据时不截屏兜底。不能承诺全量读取或零风控风险。
- **当前重点**：以微信当前会话为边界，减少从消息到完成/归档的操作步骤，保留可核对来源。

## 它怎么工作

```
微信当前可见会话 ──(无障碍读节点)──▶ 消息批次
                                        ├── 手动 Jev 意图线索（本地，不发送）
                                        └── 本地 Attention Gate
                                                  │
                                       可选 DeepSeek 事件增强
                                                  │
                                          EventStore 本地事件簿
                                                  │
                                       快捷完成 / 归档 / 来源核对
```

- **采集**：仅接受前台 `com.tencent.mm`，优先读取 `com.tencent.mm:id/bkl` 及其正文子节点。ID 变化时，必须同时确认底部编辑器、消息列表、同一行头像与可长按气泡，才使用结构兼容模式；不扫描全屏文字。服务用短节流与 1.5 秒检查恢复暂空节点。
- **门控与抽取**：`AttentionEngine` 先在本地识别行动、权威来源、@全体、DDL 和地点变化；高价值事件才调用 DeepSeek 官方 Chat Completions，并要求结构化 JSON。请求失败时保留本地结果。
- **持久化**：`EventStore` 把事件写入 App 私有 JSON 文件，先同步临时文件再原子替换；旧版 SharedPreferences 记录在首次修改时迁移。读取损坏数据或写入失败时不覆盖原文件。合并后每个事件最多保留 8 条更新、6 条依据，事件总数暂不截断。
- **消息归档**：`MessageArchive` 使用本机私有 SQLite，独立于规则和网络保存正文。邻屏重叠匹配去重；单条相同文本不视为身份，无法拼接时保留并提示缺口。分页每批 50 条，可确认后暂停观测并清空；不自动删除消息。
- **悬浮卡片**：由无障碍服务挂载 `TYPE_ACCESSIBILITY_OVERLAY`，识别时立即显示群名、手动识别入口和回溯控制。收起时也能手动识别；结果自动展开并标记依据和来源。无需另一项应用悬浮权限才能监测；关闭卡片会暂停自动回溯。
- **OCR**：中文模型随 APK 打包。只有已确认的空正文气泡区域参与识别，截图只在内存处理，结果标记“待核对”，不进入 DeepSeek 或自动事件判断。同一布局成功后不反复截屏，失败最多重试 3 次；滚动、切换页面或手动重新读取可重新触发。

本版未实现通知监听，也不通过数据库或 hook 补取不可见内容。获授权设备上的微信节点差异与实测步骤见 [微信采集 1.4](docs/wechat-capture-1.4.md)。

## 下载安装

本版本构建产物位于 `app/build/outputs/apk/debug/app-debug.apk`。请按下方说明构建当前版本。

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

优先尝试保留数据的覆盖安装。若报告签名不匹配，先确认已有数据的保留方案，不要直接卸载；卸载会删除本地事件、密钥和设置。当前交付是开发用 debug 包，不是已完成发布验收的 release 包。

## 构建

需要可运行 Gradle 8.9 的 JDK（编译目标 Java 17）和 Android SDK platform 35 / build-tools 35。最低运行版本 Android 11（API 30）。

```bash
# 用 JAVA_HOME 指向 JDK 17，local.properties 里写 sdk.dir
./gradlew assembleDebug
# 产物：app/build/outputs/apk/debug/app-debug.apk

# release 签名包：把密钥库信息写在仓库外的 properties 文件里
# （storeFile / storePassword / keyAlias / keyPassword），路径由 ATTENTION_GUARD_KEYSTORE_PROPS 指定
./gradlew assembleRelease
# 产物：app/build/outputs/apk/release/app-release.apk
```

当前 Windows 工作机从独立仓库映射的 ASCII 路径 `Y:\` 构建，避开中文路径导致的测试 worker 类加载问题；Gradle 与 SDK 位于 `K:\`。没有 release 签名配置时，release 产物为未签名包。

## 配置与授权

1. 装 APK（见上面“下载安装”，或自己构建），打开 **Attention Guard**。
2. 默认仅在本地整理。需要联网增强时，在**设置**中填写 DeepSeek API Key、测试连接并主动开启联网增强；默认模型为 `deepseek-flash`，可修改。
3. 从**我的**启用无障碍。覆盖安装后先关闭再开启一次，使新增能力重新绑定。通知、省电与自启动仍需设备侧授权；应用悬浮权限现在是可选项。
4. 打开有权查看的微信会话，观察悬浮状态，再去**来源 → 采集与回溯**检查原始消息。没有记录时用“复制诊断”，内容不含群名、正文或密钥。
5. 日期回溯：填写微信实际显示的完整会话名、起止日期，默认手动翻页；可选慢速自动翻页。准备后返回该会话，在悬浮窗点“开始回溯”。自动翻页间隔至少 4 秒，单任务最多 200 屏/200 次翻页或 15 分钟。暂停后需主动继续，重启不恢复自动操作。

密钥用 Android Keystore AES-GCM 加密存放在本机；调用 API 时会作为 HTTPS Authorization 头发送给 DeepSeek，因此不能承诺“密钥不出设备”。联网增强会发送当前会话名称、最近至多 12 条可见消息（每条正文最多 2000 字符）、相关发送者与 @ 信息、用户填写的群聊语境（最多 2000 字符），以及当前时间和本地初步事件判断。连接测试只发送内置示例。回溯任务期间的消息与 OCR 结果不进入 DeepSeek。私有事件 JSON、消息 SQLite 及回溯摘要未做应用层加密，系统备份已禁用；清空消息不会删除事件依据。

## 已知限制

- **真机覆盖有限**：只在一台获授权的 Android 17 手机、一个授权群和微信 8.0.78 上做有界检查，不能推广为所有机型/版本通过。OCR 准确率、TalkBack、长时后台、低存储和跨机型仍需验证。
- **后台与悬浮窗**：后台存活、锁屏、旋转、分屏、系统键盘遮挡、通知授权和省电策略都需要真机验证，不承诺永久后台运行或固定响应时间。
- **媒体与 OCR**：图片、文件、语音和视频仅保留有限占位符，不解析内容；OCR 有正文误识别风险。
- **群聊**：只处理当前打开、当前可见的会话；不能后台扫描全部微信群。发送者名称依赖微信当前版本暴露的节点，节点缺失时会退化为“群成员”。
- **识别准确率**：当前本地事件标题、优先级、截止时间、同类事项合并及 Jev 意图线索都是启发式规则，可能误判。DeepSeek 结构验证只保证格式，不保证事实正确，最终应核对原始依据。
- **回溯完整性**：日期从可见分隔标签解释，没有标签的消息单独计为日期未确认。未知日期、滚动过快、分页缺口、相同群名、重启或新会话任务均可能留下重复或遗漏；不得将计数当作完整历史备份。自动翻页不受支持或正文不可读时暂停，不用坐标手势盲滑。
- **后端**：当前产品界面只保留 DeepSeek 官方直连。
- **存储规模**：事件总量暂无自动清理或分页数据库，记录很多时需要进一步性能测试。API 响应有 65,536 字符上限，异常响应不会替代本地事件。
